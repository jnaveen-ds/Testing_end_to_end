Why Container Apps matches Fargate

ECS schedules containers and Fargate supplies serverless compute. Azure Container Apps presents managed compute plus HTTPS ingress, revisions, KEDA autoscaling, logs, and scale-to-zero as one platform—without managing Kubernetes nodes.

App 1 explicitly practices image → service → revision → autoscaling → scale-to-zero → rollback.

Related Azure options

  • Azure Container Instances: best for directly running a simple container, but lacks the richer API lifecycle we need.
  • Container Apps Jobs: best for one-off, scheduled, or event-driven Fargate-style tasks.
  • AKS: managed Kubernetes; powerful, but you manage more orchestration and it is outside this sprint.

Users, queues, cache, approval, and TLS

Each mechanism solves a different production problem; none is added merely to increase the service count.

Concurrent users + Redis

Container Apps replicas handle short concurrent requests. Service Bus buffers long approved jobs and caps model/tool concurrency.

App 1 uses cache-aside: normalized input + tenant scope + model + prompt version + parameters → SHA-256 key. A safe cache hit saves tokens; a miss computes once. TTL controls freshness and a distributed lock prevents a cache stampede.

Azure Managed Redis is paid and short-lived. Legacy Azure Cache for Redis cannot be created by new public-cloud customers after April 1, 2026. Use local Redis if the portal estimate threatens the cap.

Human-in-the-loop agent

FastAPI returns 202 plus a run ID. Durable Functions checkpoints the plan and waits for an external approval event without holding a request or worker.

Approve continues to Service Bus. Reject or a 10-minute durable timeout stops execution. The decision records actor, time, and immutable plan hash; duplicate decisions are idempotent.

Four lifetime controls

  1. Redis TTL: cache freshness
  2. Service Bus TTL: queued-message expiry/dead letter
  3. Approval TTL: durable workflow deadline
  4. Cosmos item TTL: old lab record cleanup

Worker execution uses a separate deadline and queue-lock renewal; message TTL does not terminate running code.

Real HTTPS, no domain purchase

Container Apps and APIM generated hostnames have trusted Microsoft-managed certificates. We inspect the chain/expiry, enforce HTTPS, and keep the APIM backend connection encrypted.

Certificates belong at ingress—not in the FastAPI image. Custom-domain DNS and managed certificates are optional only when a domain is already owned.

Why Azure requires a resource group

A resource group is a mandatory lifecycle and management boundary—not a server, network, or decorative folder.

The problem it solves

A workload can include an app, network, database, secrets, monitoring, and identities. Putting one experiment in one resource group lets us:

  • delete its resources as one lifecycle unit
  • inherit RBAC, Policy, and locks from one scope
  • review deployments and activity together
  • filter cost by resource group and tags
Every Azure resource belongs to exactly one resource group. Groups cannot be nested. The group's region stores control-plane metadata; child resources may use other supported regions.

Why today's empty group

  • Empty: learn the boundary without a billable service.
  • South India: consistent baseline for later regional choices.
  • learn-cli-0913: disposable purpose and session are visible.
  • Expiry tag: humans and automation can identify stale experiments.
  • Destroy today: cleanup is proven, not promised.

Both Client and Server must appear in docker version. A missing dockerDesktopLinuxEngine means Docker Desktop's Linux engine is stopped; start it, or update/shut down WSL and restart Docker Desktop.

Diagnose the API route and refresh a stale frontend

curl -I http://localhost:8080

docker compose exec frontend nginx -t
docker compose exec frontend wget -qO- http://api:8000/health

docker pull ghcr.io/jnaveen-ds/feedback-analyzer-frontend:latest
docker tag ghcr.io/jnaveen-ds/feedback-analyzer-frontend:latest testing_end_to_end-frontend:latest
docker compose up -d --no-build --no-deps --force-recreate frontend

pull downloads the image. tag adds a local name without copying layers. --force-recreate replaces the container; --no-deps leaves the other four services untouched.

Stop versus destroy 
docker compose stop
docker compose start
docker compose down
docker compose down -v
docker compose ps

stop preserves containers. down removes containers and the project network. down -v also deletes the test database volume. Avoid routine docker system prune -a; it affects every Docker project on the laptop.

GitHub command field guide

The protected-branch and CI workflow practiced during Day 1.

Start work safely from protected main 
gh auth status
gh repo view jnaveen-ds/Testing_end_to_end
git switch main
git pull --ff-only origin main
git switch -c <short-branch-name>
git status

Changes belong on a branch. --ff-only prevents an accidental local merge commit while updating main.

Review, push, and open a pull request 
git diff
git add <files>
git diff --cached
git commit -m "concise description"
git push -u origin <short-branch-name>
gh pr create --base main --head <short-branch-name> --fill
gh pr checks --watch
gh pr view --web

Inspect the staged diff before committing. A push publishes the branch; only a merged PR updates main.

Fix an out-of-date PR branch 
git fetch origin
git merge origin/main
git push
gh pr checks --watch

The up-to-date rule makes CI rerun against the exact combined code. If Git reports conflicts, inspect git status, resolve only marked files, add them, commit, and push. Do not force-push or discard another person's changes.
