GitHub foundation

1

Public repository

GitHub Free enforces branch protection for public repositories.

  1. Settings → General → Danger Zone
  2. Change repository visibility → Public
Security boundary changed: code and Git history are public. Never commit .env, credentials, keys, or tokens.
2

Protected main

Every change now goes through a pull request and green CI.

  • Require a pull request before merging
  • Require branches to be up to date
  • Require backend-tests and frontend-build
  • Do not allow administrator bypass

Current portal step — add the federated credential

App registration → Certificates & secrets → Federated credentials → Add credential → GitHub Actions deploying Azure resources

Keep issuer https://token.actions.githubusercontent.com and audience api://AzureADTokenExchange.

repo:jnaveen-ds@185759864/Testing_end_to_end@1350370641:ref:refs/heads/main
The numeric IDs are public, immutable GitHub identifiers. They prevent a renamed or recycled repository from inheriting this Azure trust.
Verify the public GitHub owner and repository IDs 
gh api users/jnaveen-ds --jq '{login, id}'
gh api repos/jnaveen-ds/Testing_end_to_end \
  --jq '{full_name, id, owner_id: .owner.id}'
Next — assign Azure Contributor
  1. Subscriptions → learning subscription → Access control (IAM)
  2. Add role assignment → Contributor
  3. Select User, group, or service principal
  4. Choose github-actions-testing-e2e, review, and assign

Contributor manages resources but cannot grant roles. Cost: $0.

Next — configure GitHub Actions

Repository Settings → Secrets and variables → Actions

  • AZURE_CLIENT_ID
  • AZURE_TENANT_ID
  • AZURE_SUBSCRIPTION_ID
Never add AZURE_CLIENT_SECRET. Never record secret values in documentation or chat.

Start

git clone https://github.com/jnaveen-ds/Testing_end_to_end
cd Testing_end_to_end
docker compose version

Verify

curl http://localhost:8000/health
curl http://localhost:8000/stats
curl -I http://localhost:8080
docker compose logs --tail=100 worker
Expected: db, redis, api, worker, and frontend are running. Submit feedback in the SPA and confirm pending → completed.

Destroy always

Cleanup is part of deployment—not an optional final task.

Destroy local resources

docker compose down -v
docker compose ps

The second command must show no running project services. -v removes the test database volume.
